# Chapter 14: sandbox verification and recovery

Start the local catcher with `docker compose -p careready-mail -f compose.mail.yaml up -d`. Its inbox is at http://127.0.0.1:8027; stop with the same command ending in `stop`. SMTP is deliberately loopback-only and no external relay is configured. Settings and `.env.example` document the SMTP port, public URL and 3600-second link lifetime. Never use this development transport as proof of real inbox ownership.

Signup sends a purpose-specific signed verification link; `GET /api/v1/auth/verify/{token}` marks the account verified. Protected role-based business actions now require verification. Existing unverified accounts can request a new link through `POST /api/v1/auth/verification-request` with an email address. Already-verified links return a harmless message.

`POST /api/v1/auth/password-reset-request` accepts an email and always returns the same public message. Delivery failures are recorded without recipient/link details; signup mail failure returns 503 and the already-created account can request another verification link. `POST /api/v1/auth/password-reset-confirm/{token}` accepts matching `password` and `password_confirm` fields and stores a fresh hash. Verification and reset salts differ. Links expire and tampering is rejected. One-use links and invalidating existing sessions are explicitly later hardening; password reset does not log out current sessions.
